# 发票申请

本文描述支付完成后的人工发票申请、审批、附件交付与退款边界。它覆盖余额充值和订阅购买订单的合并开票规则，不替代 Stripe 等支付渠道提供的自动账单或收据。

<a id="invoice_eligibility"></a>
## 申请范围与金额

发票申请的来源是已完成的 `PaymentOrder`，包括余额充值和订阅购买。每一条明细保存订单号、订单类型、支付时间、币种、实际支付金额和与商品有关的快照：余额订单保留兑换码及到账额度，订阅订单保留套餐名称、有效期和权益额度。它们只供核对，开票金额始终以订单 `pay_amount` 为准。

一份申请可以合并多笔订单，但所有订单必须属于同一用户、同一币种，且状态为 `COMPLETED`。明细一经提交即冻结，不能被另一份申请重复引用；只有驳回申请会释放订单占用。单笔订单不拆分到多张申请，避免重复开票和退款金额无法核对。

用户选择订单时可以查看订单号、充值/订阅类型、支付时间、支付方式和实际支付金额；订单列表支持分页，当前页全选及跨页多选仅作用于当前用户可开票订单。

## 状态与占用

申请状态为 `SUBMITTED`、`REJECTED`、`APPROVED`、`ISSUED` 和 `SENT`。当前不提供草稿、撤回或重新编辑：用户提交即进入待审批状态；被驳回后订单会释放，用户可重新创建申请。提交时快照保存发票类型、抬头、税号、可选开户行、可选银行账号、接收邮箱和账户邮箱；类型为 `PERSONAL` 或 `ENTERPRISE`，企业发票必须填写抬头和税号，开户行与银行账号用于补充开票资料但不强制，个人发票不保存企业字段。接收邮箱优先使用用户填写的邮箱，未填写时使用提交时的账户邮箱快照，之后账户资料变化不影响交付目标。

管理员可以审批或驳回，驳回必须记录原因。审批后管理员可选填发票号码、开票日期和备注；存在至少一个附件时才能标记为已开票并发送。邮件成功后状态为 `SENT`，投递失败保留 `ISSUED` 并允许重新发送。

订单被 `SUBMITTED` 及后续状态的申请占用时，不允许用户自助退款。已开票或已寄送的订单退款需由管理员先按线下作废或红冲流程处理发票申请，不能绕过发票记录直接退款。

<a id="invoice_delivery"></a>
## 附件与交付

附件持久保存，但只可由申请所有者或管理员通过受鉴权下载接口读取，不能暴露对象存储或本地存储直链。允许 PDF、JPG 和 PNG；服务在上传时校验大小、声明类型和文件签名，并记录不可变的内容哈希。审批后可追加附件，单个文件最大 10 MiB、每份申请最多 10 个；在邮件发送前管理员可删除附件，发送后附件只读保留。

新附件由统一文件存储目录 `invoice_attachments` 选择本地或私有 S3 兼容后端。附件记录写入时的后端类型和不可变存储档案 ID；切换目录配置只影响后续上传，历史附件继续按自身档案读取、发送邮件和删除。旧记录统一视为 `local-default`，保证升级后仍能读取原本地文件。

寄送邮件使用事务模板事件 `invoice.sent`，向申请的邮箱快照发送，并带上当前附件。模板支持申请编号、发票号码、抬头、合计金额、币种、订单明细和开票日期等变量。每次投递记录目标邮箱、SMTP Message-ID、附件摘要、结果与失败原因；投递失败不改变已开票事实。为控制 SMTP 报文大小，全部附件合计不得超过 20 MiB。

<a id="invoice_security"></a>
## 安全与审计

发票抬头、税号、开户行、银行账号、邮箱和附件属于敏感业务资料。列表接口按权限最小化返回，日志不输出税号、银行账号、原始附件内容或可直接访问的文件路径。提交、审批、驳回、开票、附件上传、下载和邮件投递都必须具有可追溯的操作者、时间和结果。
